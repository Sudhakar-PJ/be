Milestone 1 — Step 11: The Cryptographic Engine (src/lib/crypto.ts)
In modern security architecture, we never use a one-size-fits-all hashing algorithm. Different data requires completely different cryptographic guarantees:

┌─────────────────────────────────┬─────────────────────────────────┬─────────────────────────────────┐
│ 1. Passwords (Argon2id)         │ 2. Access Tokens (RS256 JWT)    │ 3. Refresh Tokens (SHA-256)     │
├─────────────────────────────────┼─────────────────────────────────┼─────────────────────────────────┤
│ • High human entropy is LOW     │ • Asymmetric public/private key │ • Raw random entropy is HUGE    │
│   (passwords are short/simple). │ • Only auth service signs with  │   (256 bits of random bytes).   │
│ • Must be SLOW and MEMORY-HARD  │   private key.                  │ • Password crackers cannot brute│
│   to defeat GPU cracking rigs.  │ • Any service verifies with the │   force 256-bit random tokens.  │
│ • Argon2id (RFC 9106)           │   public key.                   │ • Fast SHA-256 is ideal here.   │
└─────────────────────────────────┴─────────────────────────────────┴─────────────────────────────────┘
Understanding the 3 Cryptographic Components:
1. Argon2id Password Hashing (argon2)
Won the Password Hashing Competition (defeating bcrypt and scrypt).
Memory-hard: Forces an attacker's GPU to allocate tens of megabytes of RAM per attempt, making mass parallel cracking hardware-impossible.
2. Asymmetric RS256 JWTs (jsonwebtoken)
Symmetric HS256 (Junior): Both signer and verifier share the same secret password. If any microservice or developer leaks the secret, an attacker can forge admin tokens.
Asymmetric RS256 (Senior):
The backend signs access tokens using an RSA Private Key.
Any gateway or service verifies tokens using only the RSA Public Key. Even if your public key is published on the internet (like GitHub/Google do via /.well-known/jwks.json), no one can forge a token!
3. Opaque Refresh Tokens & High-Entropy SHA-256 Hashing (node:crypto)
We generate 32 bytes of cryptographic randomness (crypto.randomBytes(32).toString("hex")).
The user receives the raw token.
The database only stores the hashToken(token) using SHA-256. If your database is ever leaked, the attacker cannot use the hashed tokens to authenticate.
Action 1: Create 01-saas-api/src/lib/crypto.ts
Create src/lib/crypto.ts:

typescript
import argon2 from "argon2";
import jwt from "jsonwebtoken";
import crypto from "node:crypto";
import { env } from "../config/env";
import { UnauthorizedError } from "./apiError";
export interface AccessTokenPayload {
  sub: string;      // User ID (UUID v7)
  email: string;
}
// ---------------------------------------------------------
// 1. Password Hashing (Argon2id)
// ---------------------------------------------------------
export async function hashPassword(password: string): Promise<string> {
  return argon2.hash(password, {
    type: argon2.argon2id,
    memoryCost: 65536, // 64 MB of RAM per hash
    timeCost: 3,       // 3 iterations
    parallelism: 4,    // 4 parallel threads
  });
}
export async function verifyPassword(
  password: string,
  hash: string
): Promise<boolean> {
  try {
    return await argon2.verify(hash, password);
  } catch {
    return false;
  }
}
// ---------------------------------------------------------
// 2. Access Token Management (Asymmetric RS256 JWT)
// ---------------------------------------------------------
export function signAccessToken(payload: AccessTokenPayload): string {
  // Format private key: replace literal escaped '\n' with real newlines
  const privateKey = env.JWT_ACCESS_PRIVATE_KEY.replace(/\\n/g, "\n");
  return jwt.sign(payload, privateKey, {
    algorithm: "RS256",
    expiresIn: env.JWT_ACCESS_EXPIRES_IN as jwt.SignOptions["expiresIn"],
  });
}
export function verifyAccessToken(token: string): AccessTokenPayload {
  try {
    const publicKey = env.JWT_ACCESS_PUBLIC_KEY.replace(/\\n/g, "\n");
    const decoded = jwt.verify(token, publicKey, {
      algorithms: ["RS256"],
    }) as jwt.JwtPayload;
    if (!decoded.sub || !decoded.email) {
      throw new UnauthorizedError("Invalid token payload structure");
    }
    return {
      sub: decoded.sub,
      email: decoded.email,
    };
  } catch (error) {
    if (error instanceof jwt.TokenExpiredError) {
      throw new UnauthorizedError("Access token has expired");
    }
    if (error instanceof jwt.JsonWebTokenError) {
      throw new UnauthorizedError("Invalid access token");
    }
    throw error;
  }
}
// ---------------------------------------------------------
// 3. High-Entropy Opaque Tokens & SHA-256 Hashing
// ---------------------------------------------------------
export function generateOpaqueToken(): { rawToken: string; tokenHash: string } {
  // 32 random bytes = 256 bits of entropy = 64 hex characters
  const rawToken = crypto.randomBytes(32).toString("hex");
  const tokenHash = hashToken(rawToken);
  return { rawToken, tokenHash };
}
export function hashToken(token: string): string {
  return crypto.createHash("sha256").update(token).digest("hex");
}
Action 2: Generate an RSA Key Pair for .env
RS256 requires a real RSA key pair (Private key to sign, Public key to verify).

You can generate a 2048-bit key pair directly in your terminal using Node's built-in crypto module:

bash
node -e '
const { generateKeyPairSync } = require("crypto");
const { privateKey, publicKey } = generateKeyPairSync("rsa", {
  modulusLength: 2048,
  publicKeyEncoding: { type: "spki", format: "pem" },
  privateKeyEncoding: { type: "pkcs8", format: "pem" }
});
console.log("\n--- COPY TO JWT_ACCESS_PRIVATE_KEY ---");
console.log(JSON.stringify(privateKey));
console.log("\n--- COPY TO JWT_ACCESS_PUBLIC_KEY ---");
console.log(JSON.stringify(publicKey));
'
Copy the two output strings into your .env file:

env
JWT_ACCESS_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvgIBADANBgk..."
JWT_ACCESS_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkqhki..."
